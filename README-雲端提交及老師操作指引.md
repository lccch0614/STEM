# 營養惜食工作坊：雲端提交版本

適用網站：https://lccch0614.github.io/STEM/  
老師管理頁：https://lccch0614.github.io/STEM/teacher.html  
儲存服務：https://food-workshop-api.lccch.workers.dev  
更新日期：2026-10-27

## 這次更新

學生完成食譜及概念圖後，填工作坊代碼及學生編號，按一次「提交」。食譜及壓縮後的概念圖一起存入 Cloudflare D1；系統核對兩者均能讀取後，才顯示可帶回家的作品 QR code。提交本身不會再次呼叫 AI，也不會產生另一張圖片。

家長掃作品 QR code，會開啟 GitHub Pages 的固定家長頁，再讀取 Cloudflare 已保存的食譜及圖片。家長不需要帳戶或工作坊代碼。作品網址中的識別碼固定；新提交會產生另一個版本，已派發 QR 的舊版本會保留。

四位老師登入同一管理頁、選同一工作坊，即可查看相同的提交進度，每 15 秒更新。老師可以預覽、選印、批准圖片失敗時的文字後備、重設學生裝置，以及下載全班備份。

原本的下載收檔及匯入功能保留在老師後備選項內。

## 一次性的啟用步驟

1. Cloudflare 已部署 `food-workshop-api`，D1 binding 名稱是 `DB`，資料庫是 `food-workshop-db`。
2. 老師在 Cloudflare 的 Runtime variables and secrets 新增 Production **Secret**：Key 為 `TEACHER_KEY`，Value 自訂至少 16 個字元，並按部署。管理碼只供老師使用，不要寫進 GitHub 或傳給學生。
3. 開啟 https://food-workshop-api.lccch.workers.dev/check ，由老師輸入同一管理碼，按「執行一次儲存及圖片測試」。應看到成功訊息、`status: passed` 及測試圖片。測試不會呼叫 AI，會建立一個已停止收件的虛構測試工作坊。
4. 將更新 ZIP 解壓，把其中網站檔案按原有目錄位置上傳到 GitHub 的 `STEM` 網站根目錄，覆蓋同名檔案；`vendor` 內的檔案放回 `vendor`。不要上傳整個外層資料夾，也不要上傳 Worker 備份到網站。ZIP 的 README 可不用上傳。
5. 等 GitHub Pages 發布完成後，重新整理網站。開老師頁登入、建立正式工作坊，再用一部學生裝置完整試一次提交。用另一部手機掃作品 QR，確認家長頁的菜名、步驟及圖片正確。

更新 ZIP 包含本次 11 個檔案及之前發布／文字模型修正所需的相依檔案。它不包含 `script.js`，保留你現有的 AI 設定；也不包含測試學生作品或老師管理碼。

## 星期五前：老師準備

1. 一位老師建立一個正式工作坊，例如「10月30日營養惜食工作坊」，人數填 **30**，設定收件截止時間。其餘老師登入後，選同一個工作坊，毋須各自建立。
2. 將加入網址或加入 QR code 放在投影片；學生由加入網址進入，工作坊代碼會預填。每人使用指定的 **1–30 號**，不要重複。作品名稱可用暱稱，避免輸入姓名、聯絡資料或其他私人資料。
3. 用學校實際 Wi-Fi 及學生裝置試完整流程：生成食譜 → 生成一張概念圖 → 提交 → 老師收到 → 另一部手機掃作品 QR。
4. 先試印一頁：A4、實際大小 **100%**、關閉頁首頁尾，量度貼片及掃碼。軟件測試未能代替學校實際打印機及磁貼試印。

## 60 分鐘工作坊建議

- 0–10 分鐘：情境挑戰及營養／惜食重點。
- 10–30 分鐘：選材料、常用份量，閱讀 AI 建議並調整食譜。
- 30–40 分鐘：完成菜名及步驟，生成一張概念圖。
- 40–45 分鐘：學生提交，四位老師分別協助約 7–8 位學生，確認全班收齊。
- 45–60 分鐘：一位老師集中選印，其餘老師協助裁切、配對學生編號、試掃及製作磁貼。

## 學生操作

1. 保持使用同一部裝置及同一個瀏覽器完成工作。
2. 完成食譜及概念圖，填正確工作坊代碼及學生編號，再按提交。
3. 看到「已成功儲存於雲端」及作品 QR code，才算提交完成。老師管理頁應同時顯示有圖片的作品。
4. 修改食譜後要重新提交，才會產生包含修改的新版本。每位學生最多保留 **5 個提交版本**。網絡失敗後可手動再按提交；相同內容會返回同一作品，不會新增重複版本，也不會自動重新生成 AI 圖片。

圖片未完成時，正常流程不接受提交。若圖片生成一直失敗，老師可在該學生的「老師協助」批准「文字後備」；學生也須確認使用文字後備。老師印前會看到該作品沒有圖片。

## 列印 5×5 cm 亞加力磁貼

1. 老師核對學生編號、菜名及圖片，選取要印的作品。首次可用「選取全部已提交作品」。
2. 按「核對及列印所選磁貼」。系統會先讀取及核對所選版本的食譜及圖片，再開列印。
3. 每張貼片 **48×48 mm**，中央 QR code **40 mm**；A4 每頁 **15 張**，30 位學生共 **2 頁**。選實際大小 100%，關閉頁首頁尾，不要使用「符合頁面」縮放。
4. 保留 QR 周圍白邊，勿把裝飾、姓名或膠帶圖案蓋在 QR 上；裁切後按學生編號配對，貼入 5×5 cm 亞加力，完成後再掃一次。
5. 作品有多個版本時，可選採用版本；老師頁會保留上次選印的版本。如出現「有新版本」，先決定是否重印，已派發的舊 QR 仍指向舊作品。

## 常見情況

- **編號已被另一部裝置使用**：先核對是否輸錯編號；真的換裝置時，由老師使用「重設裝置」。舊裝置的提交權限會失效，已保存作品保留。
- **管理登入失效**：管理登入有效 12 小時，重新登入即可。四位老師可各自登入，離開共用裝置時登出。
- **學生提交失敗**：草稿仍在原裝置。檢查代碼、編號、截止時間及網絡，解決後手動再提交；錯誤不會觸發 AI 重試或自動轉模型。
- **老師未看到最新提交**：等最多 15 秒，或按重新整理。學生應以成功訊息及作品 QR 為準。
- **停止收件**：只會停止新加入及新提交，已保存的家長頁和圖片仍可讀取。

## 保存、備份及邊界

- 正式食譜及圖片存在老師 Cloudflare 帳戶的 D1；GitHub 只放網站程式及固定家長頁入口。學生不需要 GitHub 帳戶。
- 目前程式沒有為已保存作品設定自動刪除日期；但服務不保證永久。需持續保留 GitHub Pages、Cloudflare Worker、D1 資料及原本網址；取消服務、刪除資料、改網域或平台限制都可能影響讀取。知道作品網址的人可以讀取該作品，請勿保存敏感個人資料。
- 活動結束後，按「下載全班作品備份」。ZIP 包含所有已提交版本、圖片、可離線閱讀的 HTML、作品資料、學生編號及原網址。解壓並保留整個目錄即可閱讀。這是備份；本版沒有把 ZIP 自動還原至雲端的按鈕。
- 每個工作坊最多 60 位學生，每人最多 5 版本；服務設定最多 20 個工作坊、共 800 個作品。儲存用圖片會壓縮為 JPEG，最長邊不超過 1024 像素，每張最多約 350 KB。這些是本版程式上限，並非 Cloudflare 方案容量承諾。
- 文字及繪圖 AI 仍使用現有設定；本次儲存更新沒有改成 AI 代理或加上伺服器用量限制。儲存成功也不代表 AI 對營養或烹調安全的建議已獲專業核實，印前應由老師檢視。
