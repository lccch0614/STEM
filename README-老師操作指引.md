# 60分鐘工作坊：四位老師收檔及上傳指引

版本：2026-10-26；30位學生，每人一部裝置；5×5cm亞加力磁貼。
正式網站：https://lccch0614.github.io/STEM/

## 概念圖會儲存在哪裏？

生成成功後，網站會把概念圖轉成適合網頁的JPEG，自動儲存在該學生裝置的瀏覽器IndexedDB，同時保留食譜草稿。重新開啟同一網址、同一瀏覽器及使用者設定檔，可以恢復，不會再次呼叫AI。

這是本機儲存，未會自動傳給老師或GitHub。清除網站資料、私密瀏覽、換裝置，均可能令本機記錄消失。因此每位學生完成後須下載「食譜＋概念圖作品包」。只有在老師明確選擇文字後備時，作品包才可以不含圖片。

正常作品包包括食譜、圖片及相互核對資料。老師匯入後，系統會自動配對，毋須逐張圖片改名。正式家長頁包含同一張已保存圖片、材料、步驟、致敏物提醒、營養估算及親子煮食提示。開啟家長頁不會使用AI額度。

修改材料、份量、做法或菜名後，原圖會失效，避免錯配。純粹轉換圖片模型會保留已有圖片；重新生成成功後才取代圖片。圖片請求失敗不會自動重試或轉模型。

## 課前：先更新網站

1. 解壓「workshop-publishing-update-2026-10-26.zip」。
2. 將解壓後的8個更新檔上傳至現有STEM專案相同位置，保留子資料夾結構。index.html、workshop.js、workshop-core.js及publication三個檔案在根目錄；JSZip兩個檔案在vendor資料夾。
3. 保留現有script.js、style.css、食材資料、圖鑑及情境挑戰檔案。本更新包不含script.js，現有API設定不用重新填寫。
4. 等GitHub Pages完成更新後，重新整理網站。智能餐盤下方應看到「老師收集台：收檔 → 匯入 → 上傳 → 列印」。若仍是舊版，使用強制重新整理。
5. 四位老師均使用正常瀏覽模式開啟正式網站，核對「老師列印設定」的網址是上述正式網址。先約定一種交檔方式，例如學校Drive資料夾、課堂平台；裝置支援時亦可AirDrop。網站本身不會發送檔案。
6. 用工作坊的實際裝置和校內網絡，完成一份真實食譜及一次概念圖生成，再走一次以下上傳及列印程序。本次程式驗證使用模擬AI回覆，未驗證校內網絡／香港帳戶的付費模型連線，也未作實體打印。

## 學生：只需交一個檔案

1. 選材料及常用份量，生成／修改食譜。
2. 按「生成概念圖（付費）」，成功後會顯示自動儲存狀態。
3. 以暱稱或作品代號記認，不要輸入全名、聯絡方法等資料。
4. 按「下載食譜＋概念圖作品包」。檔名是w-代號.foodwork.zip，通常在「下載項目」；iPad可在檔案App的下載項目尋找，實際位置依瀏覽器設定。
5. 把原裝ZIP檔交給負責老師。不要解壓、重新壓縮或只交圖片。若已自動解壓，請回網站重新下載原裝作品包。

如圖片失敗：先找老師。老師可手動重試一次（會另發請求），或在「老師後備選項」確認交文字版。此時家長頁會明確說明使用文字後備，並非假裝附有圖片。

## 四位老師分工

建議老師A兼統籌，收8位；B收8位；C、D各收7位。每位老師在自己的裝置完成：

1. 儲存學生交來的ZIP到自己的資料夾。
2. 打開網站的「老師收集台」，按「匯入作品／老師收集包」，可一次選多個ZIP。
3. 核對暱稱、菜名、「含概念圖」及預期份數；可按「預覽」查看食譜及圖片。
4. 同一版本重複交檔會略過。修改菜名／內容／圖片後會產生新作品代號；若學生交了多個版本，請先確認採用哪份，再移除本機收集台中不採用的版本，保留原始檔備份。
5. 按「下載老師收集包」。B、C、D把各自收集包交給A。A匯入三個收集包後，應有30份採用作品，再下載一份總收集包備份。

各老師的收集台不會跨裝置同步。只有統籌老師需要登入GitHub，其他老師只需傳檔；不要把GitHub憑證放入網站。

## 統籌老師：上傳家長頁及圖片

1. 在已有30份定稿的收集台按「下載GitHub上傳包」。
2. 解壓ZIP，會得到r資料夾及上傳說明。r內每份正常作品各有一個HTML及一張同名JPEG；30份作品通常合共60個檔案。文字後備只有HTML。
3. 在GitHub開啟STEM repository的根目錄，即index.html所在一層，使用Add file → Upload files，把整個r資料夾加入，確認檔案路徑是r/w-代號.html及r/w-代號.jpg，然後提交。
4. 不要只把ZIP檔直接放上GitHub。不要把r資料夾放進data、vendor或另一層STEM資料夾，也不要刪除原有r內的舊作品。
5. 等GitHub Pages部署完成，返回同一部裝置的老師收集台，按「核對上線作品及圖片」。系統會檢查每份頁面版本及圖片內容。
6. 全部核對成功後才會開放「列印已核對磁貼」。如有404或圖片不一致，先檢查路徑／是否漏圖／部署進度，再重新核對，勿先派發磁貼。

正式網址形如：https://lccch0614.github.io/STEM/r/w-xxxxxxxxxxxxxxxxxxxxxxxx.html 。QR內只有固定網址，所以適合小型貼片。內容修改會產生新代號，不會偷偷改寫已派發磁貼所指向的舊作品。

網址沒有設定到期日，但不是永久保證：STEM網站及相應HTML、JPEG需要一直保留，GitHub Pages亦需繼續提供服務。改repository名稱／網址、刪除舊作品或停用Pages，都可能令舊QR失效。家長不需要學生裝置的本機資料，也不需要API key。

## 列印及貼上5×5cm亞加力

- 使用「列印已核對磁貼」，每張48×48mm，QR為40×40mm（含白邊）；每頁A4排15張，30份共2頁。
- 列印設定：A4直向、實際大小／100%、關閉頁首頁尾；不要選縮放至符合頁面。
- 先試印一頁，以尺量度48mm外框；用老師或家長手機掃碼，確認文字及概念圖都可顯示。
- 沿虛線剪出貼片，保留QR內白邊。貼片在50×50mm亞加力上每邊約餘1mm；避免氣泡及強烈反光。
- 菜名很長時，只會縮略貼片上的單行標題；家長頁材料及步驟完整保留。

## 60分鐘節奏建議

0–5分鐘介紹；5–13分鐘完成一個情境挑戰；13–20分鐘選材料及觀察份量；20–32分鐘生成／修改食譜；32–40分鐘完成概念圖及交作品包；40–50分鐘老師合併、上傳及核對，學生分享設計；50–60分鐘列印、試掃、剪貼及製作磁貼。

盡量第40分鐘前收齊定稿，留足部署及列印時間。可由B、C、D協助學生分享及剪貼，A處理GitHub與打印。
